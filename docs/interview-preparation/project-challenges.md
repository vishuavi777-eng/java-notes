# Project Challenges

## Question

What challenges did you face in your project?

## Main Answer

One of the main challenges in my project was handling complex diet business logic in the Diet Engine system.

Different users had different health goals, food preferences, allergies, and diet restrictions. Some users required carb cycling, some needed meal replacements, and some required dynamic changes in meal plans based on their progress. Creating reusable and flexible logic for all these conditions was challenging.

To solve this, I designed modular business logic and database structures so rules could be managed more easily and updated without affecting the full system.

Another challenge was customer support call automation. Earlier, calls were managed manually. While developing the automation system, we had to avoid duplicate call assignments, manage priorities, and schedule calls correctly based on different conditions.

Performance was also an important challenge because the system handled large amounts of user and diet data. Some APIs and database queries became slow as data increased. I optimized database queries, improved API flow, and reduced unnecessary processing to improve performance.

We also faced challenges with changing business requirements. In the healthcare and nutrition domain, diet rules and workflows changed frequently. Because of this, I tried to create reusable and configurable logic instead of hardcoded solutions.

Another challenge was maintaining proper synchronization between mobile apps, backend APIs, and admin panels. We had to ensure that users always received updated meal plans and correct data.

I also handled production issues and debugging when real users faced problems. This helped me improve my debugging and problem-solving skills.

## Challenge vs Solution Table

| Challenge | Solution |
| --- | --- |
| Complex diet rules | Created modular and reusable business logic |
| Dynamic meal plan changes | Designed flexible database structure |
| Duplicate call allocation | Added scheduling and validation logic |
| Slow APIs and queries | Optimized database queries and API flow |
| Frequent requirement changes | Used configurable logic instead of hardcoding |
| Mobile app sync issues | Improved API response handling and data flow |
| Production bugs | Used debugging, logging, and quick issue fixing |

## Short Version

One major challenge was handling complex diet business logic because different users had different food rules, goals, and diet plans. I solved this by creating reusable and flexible backend logic.

Another challenge was automating customer support call allocation without duplicate scheduling. I implemented validation and scheduling logic for that.

We also faced API performance and data synchronization challenges, which I improved through query optimization and better backend flow.

## Key Points to Remember

- Focus on real business challenges.
- Explain both challenge and solution.
- Mention scalability and reusable logic.
- Mention debugging and production support.
- Speak confidently about automation problems.
- Avoid saying everything was easy.
